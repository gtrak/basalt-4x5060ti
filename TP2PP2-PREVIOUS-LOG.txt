# TP=2 / PP=2 exploratory branch — design brief
## Mission
Add an exploratory tensor-parallel-2 × pipeline-parallel-2 execution mode to the
basalt engine, behind a flag, sufficient to MEASURE the decode window and prefill
against the current layer-split baseline. This is an exploration branch: honest
plumbing over polish, every assumption written down, no claim without a number or
an explicit "unmeasured."
## Hard constraints
1. **The production server is LIVE and must not be touched.** Never run
   `basalt-ctl`, never signal any `basalt`/python process, never bind port 8000.
   There is no restart in this milestone. Verification = the build compiles, the
   unit tests that exist pass, and a written runbook for the eventual restart.
2. Builds: `cmake --build build -j4` (NOT -j8: the live server's host threads
   share this CPU; a full-tilt build visibly stalls it). Use the worktree's own
   `build/` dir.
3. Commit in logical units as you go (the branch is the deliverable); the commit
   style of `git log --oneline -15` on main is the house style: lowercase area
   prefix, the why in the body with numbers.
## Topology (the design)
- Cards 0,1 = **stage A** (layers 0–23), cards 2,3 = **stage B** (24–47). The
  existing stage machinery (`stages`, the per-stage carve, `bslot_ss`,
  `set_stage`, the handoff buffers) is the scaffold — TP=2 means each STAGE
  becomes a *pair* of cards computing cooperatively instead of one card
  sequentially owning its layer range.
- **Attention**: head-split within the pair. Each card computes half the heads
  (KV also head-sharded — ¼ of the full KV per card). Head-split attention is
  bitwise-exact: no numerics gate for it.
- **Dense/FFN (non-MoE) linears**: row-split within the pair, partial sums
  reduced by a 2-way all-reduce. NOTE: changes reduction order → the numerics
  gate applies (document; do not implement the gate).
- **MoE experts**: EP-within-pair — each card holds HALF the experts for its
  stage's layers (≈15.8 GiB/card, same VRAM as today). Tokens routed to the
  peer's experts go by the EXISTING d2d machinery (`set_ring_remotes` /
  the tier's copy path). No expert weight sharding in this branch (the
  small-GEMM collapse + numerics gate — rejected, see WORKLOG rationale).
- **Collectives**: 2-way all-reduce = each card copies its full buffer to its
  peer over `cudaMemcpyPeerAsync` (peer access is already enabled at start) and
  adds locally — ONE exchange per collective on 2 ranks. Implement a small
  helper (`tp2_all_reduce(buf, rows, stride, stream, peer_dev)`) in the kernels
  layer; do NOT pull in NCCL for the exploration (the sglang worklog lesson:
  on this PCIe/PHB box an IPC-buffer exchange beats the NCCL ring; NCCL is a
  later production decision).
- **KV/session**: each card in the pair holds its head-shard's KV. The slot
  model's `slot_cap` semantics must hold per pair (a slot's conversation spans
  the pair's two shards).
## Codebase map (what matters, from a measured campaign on this exact box)
- `src/program/generate.cpp` (~11k lines): the serve loop, `stages` + the carve
  (per-stage layer ranges and sessions), `read_part` (prompt reads — on this
  branch leave the split's exclusive-read policy alone), the batch windows
  (`ver.run_slot_segs`), `set_ring_remotes` call sites, the decode-timing log
  line (~10600+), `ov_active`.
- `src/prefill/prefill.cpp` + `include/basalt/prefill/prefill.hpp`:
  `set_ring_remotes` — the d2d expert copy path the pair's EP reuses.
- `src/core/expert_source.cpp` + `include/basalt/core/expert_source.hpp`:
  the expert cache/slots/blob layout (`expert_layout()`, `blob_bytes`), the
  complement/pin logic, the budget contract (do not weaken it).
- The price model (`plan_multi_gpu` / `auto_plan.cpp`): tier 27.0, split 31.2,
  tp 24.7 (not built). Leave the model alone; the new mechanism is flag-gated
  (`BASALT_TP2=1` env or `--tp-size 2`), default off, and the model's TP line
  stays aspirational until measured.
- Baselines to beat/compare (measured, 4× 5060 Ti gen4 x4, NVFP4 pack, 150k ctx):
  decode window 34.7–38.7 ms (72–88 tok/s per conversation), fresh prefill
  3750–3898 tok/s exclusive, TTFT on cached 150k turns 0.2–2.5 s.
- TP=2/PP=2 napkin target: window ~20–24 ms (2 stage handoffs not 4, halved
  per-layer compute, 48 × ~30 µs pair-collectives ≈ 1.5–4 ms comm).
## Scope for THIS branch (milestones, in order, each committed)
1. **M1 — scaffold**: the flag; stage-pair construction (2 stages × 2 cards);
   expert EP-within-pair reusing the existing routing; expert VRAM carve at half
   depth per card; build green; the boot log names the topology

2. **M2 — attention head-split + the 2-way all-reduce helper.** Unit-testable

3. **M3 — dense/FFN row-split** + wire the collectives into the verify path.
4. **M4 — measurement runbook** (TP2PP2-RUNBOOK.md): the exact commands, the

   hit rate, prefill t/s), and the rollback (the flag default-off = today's

Out of scope: numerics gate, NCCL, expert weight sharding, --tp-size 4,
production polish, the price model wiring.

# Building and testing
Clone, requirements and the build commands are in the [README](../README.md). This page has the rest.
## What is in the repository
- `src/`, `include/`: the C++/CUDA engine (one binary, `basalt`).
- `serve/`: a Python server with an OpenAI- and Anthropic-compatible API, and a stats page.
- `tools/convert/`: the model-file converter (`convert.py`), its section builders and the drafter fetcher (`mtp_fetch.py`).
- `tools/`: the .basalt reader and writer (`model_file.py`), the PPL/KLD quality gate (`ppl_gate.py`), the greedy-identity
  check and the tokenizer.
- `tests/`: parity and unit tests.
## Tests
The tests are off by default. Configure the README's build with the extra option `-DBUILD_TESTING=ON`, build, then run `ctest --test-dir build`.
The kernel parity tests need the GPU; the file-format, cache and memory unit tests do not. `expert_parity` and `pool_test`
run on a synthetic expert fixture; pass `--file experts.bin` (the pack's experts section, not shipped) to check real blobs.
`platform_memory_test` locks 256 MiB when the locked-memory limit (`ulimit -l`) allows it and a smaller region otherwise,
and says so; it skips the lock case only when the limit is too low to lock anything.
The server tests run with `python -m unittest discover -s serve/tests -t .` after `pip install -r requirements-test.txt`
(the server's requirements). Two tokenizer tests read the pack's
vocabulary and skip without a pack; the same checks run on a synthetic vocabulary in the same file. The test that runs
the built engine with every flag needs `bin/basalt`.
The engine tokenizes request text itself (`GENT`). `tokenizer_test` checks the C++ tokenizer on a synthetic vocabulary;
`tokenizer_parity` compares its ids with `tools/tokenizer.py` over a corpus, and is registered when cmake gets
`-DBASALT_TOKENIZER_DIR=<a pack's extracted tokenizer/ directory>` (with python3 and the `regex` package; `-DBASALT_TOKENIZER_BIG`
adds `--big FILE...` to the corpus). `tokenizer_bench DIR FILE...` times a cold and a warm encode.
`basalt-bench` reads its pre-tokenized prompts from `data/bench` (token ids for the Qwen3.8-Flash-Next tokenizer: the
three decode prompts and a prefill filler); run it from the repository root or pass `--fixtures DIR`. `basalt-bench
--help` says how the files are made.
The build needs nothing outside this repository and fetches nothing. The parts of ggml and llama.cpp that Basalt uses
(quantization formats, CPU dot products, the prompt path's MMQ kernels) are extracted into `src/` and `include/basalt/ggml/`,
with their MIT licence in `THIRD_PARTY_LICENSES`.
`basalt-bench --community` runs the fixed preset `community-1` for the public table in [community runs](community.md):
the three decode fixtures, a 16384-token prefill and a 65536-token prefill, each once, with int8 KV cache and the
engine's own defaults otherwise (drafting included). The decode fixtures and each prefill run in their own fresh engine
process, with no warm-up pass and no repetition, so every number is the cold first run. It
prints the usual table, adds its row to `docs/community/benchmarks.json` of the checkout the build came from (`--community-file PATH` picks another file) and prints it. Review the row, commit it and open a pull request:
```sh
bin/basalt-bench --community --model Qwen3.8-FN-NVFP4.basalt --submitter "Your Name"
```
`prefill_16k_tps` and `prefill_64k_tps` are the engine tokens per second of those two prompts; `decode_tps` is the generated tokens of conv, struct and prose over their summed decode time (token-weighted). The row
records the engine commit, the GPUs the engine used (main first) with VRAM and enforced power limit from NVML, system
RAM, the OS (`Linux`, `Windows` or `WSL2`), the pack's quant label. Every expert must sit in VRAM, the peer GPU or RAM: if the engine would read any from the SSD, the bench stops before measuring, says how many GiB would spill and roughly how much more free RAM is needed, exits non-zero and prints no row. NVML is required;
without it, or without a git build, the run stops with a message. Only `--model`, `--submitter`, `--fixtures` (the
repository's `data/bench`), `--logs` and `--print-command` are accepted: any other bench option or engine flag changes
the workload and is refused. The run uses every visible Blackwell GPU (`--gpu auto`; `--gpu` is refused); pick the cards with
`CUDA_VISIBLE_DEVICES`, for example `CUDA_VISIBLE_DEVICES=0` for a single-GPU row. The preset's version changes whenever the workload does.

// glue in the per-layer graph, and glue that is written inline at each call site is glue with several
// slightly different float conventions.  Three of them exist because a projection returns a DIFFERENT
// quantity from the one the next kernel wants:
//
//   * `gdn_gate` turns (alpha, dt, ssm_a) into the recurrence's `gate`.  the reference:
//     `gate = softplus(w_alpha . x + dt) * ssm_a`, with `softplus(x) = log1p(exp(x))` and the large-x branch
//     `ggml_compute_softplus_f32` uses.  `ssm_a` is NEGATIVE, which is what puts `exp(gate)` in (0,1).

__global__ void embedding_gather_kernel(const uint8_t* __restrict__ codes,
                                       const float* __restrict__ scales,
                                       const float* __restrict__ offsets, int64_t n,
                                       int code_bits, int code_bias, int group_elems,
                                       float* __restrict__ out) {
    const int64_t i = (int64_t) blockIdx.x * blockDim.x + threadIdx.x;
    if (i >= n) return;
    const int per_byte = 8 / code_bits;
    const unsigned mask = (1u << code_bits) - 1u;
    const int code = (codes[i / per_byte] >> ((i % per_byte) * code_bits)) & mask;
    const int64_t group = i / group_elems;
    const float product = __fmul_rn((float) (code + code_bias), scales[group]);
    out[i] = __fadd_rn(product, offsets ? offsets[group] : 0.0f);
}
/// `ggml_compute_softplus_f32`: `log1p(exp(x))`, with the large-x branch that avoids overflow.
///
/// The branch is not cosmetic. `exp(89)` overflows f32 and `exp(20)` is already 4.85e8 where `log1p` loses
/// relative precision; above 20 the function is `x` to within f32 anyway.
__device__ __forceinline__ float softplus_dev(float x) { return x > 20.0f ? x : log1pf(expf(x)); }
__global__ void gdn_gate_kernel(const float* __restrict__ alpha, const float* __restrict__ dt,
                                const float* __restrict__ ssm_a, float* __restrict__ gate, int64_t h_v) {
    const int64_t i = (int64_t) blockIdx.x * blockDim.x + threadIdx.x;
    if (i >= h_v) return;
    const int64_t t = i / h_v;      // `n_tokens` is the leading dim; the real call has one token
    const int64_t h = i % h_v;
    gate[i] = softplus_dev(alpha[i] + dt[h]) * ssm_a[h];
    (void) t;
}

}

// include/basalt/core/session.hpp - ONE TOKEN through all 48 layers, and the doorbell protocol between them.
//
// The host loop, and the place the engine runs a whole forward pass rather than one block.  What it owns is the ORDER
// across layers and the state that outlives a layer:
//
//   * the gated residual stack `R` - (hc, n_embd), which every block reads and writes;
//   * 12 QSA states (KV cache + indexer) and 36 GDN states (recurrence + conv history), because `is_qsa_layer`
//     splits the 48 layers 12/36 and the two kinds of state have nothing in common;
//   * the per-token expert handoff, which is where the CPU pool meets the GPU.
//
// WHY THE LAYER GRAPHS ARE CAPTURED AND THE LOOP IS NOT.  A graph bakes in its arguments, so the graph unit is ONE
// LAYER: everything per-token (the position, the step counts) arrives through fixed-address device buffers, and the
// HOST decides when each layer runs.  That decision is the whole point - it is what lets the CPU expert pool start
// while the GPU is still working on the next layer.

// include/basalt/core/peer_experts.hpp - multi-GPU: a second expert tier on another GPU.
//
// The primary GPU (device 0) keeps everything it had: the dense weights, the KV cache, the MTP layer, its own
// adaptive expert tier and the captured verify graph.  This class adds an expert tier on a SECOND card.  From
// the verify graph's point of view nothing changes: for each layer the pool thread decides which routed experts
// the primary computes (its VRAM tier, the PCIe share), and every remaining expert is a "CPU row" the graph reads
// from mapped host memory after the pool raises its flag.  The peer takes the rows whose experts it holds: the
// pool thread launches them on the peer right after publishing the primary's plan, the CPU computes the rest at
// the same time, and the peer's rows are written into the same mapped rows before the pool returns.
//
// The peer computes with the SAME kernels as the primary's hit path (q8_1 activations + native_expert_grouped),
// from the same activation values, so an expert gives bit-identical rows on either card.
//
// The tier follows the conversation like the primary's: `adapt` swaps the most-routed experts that neither card
// holds into the peer's least-used slots (per layer, so a slot keeps its layer's blob size).
